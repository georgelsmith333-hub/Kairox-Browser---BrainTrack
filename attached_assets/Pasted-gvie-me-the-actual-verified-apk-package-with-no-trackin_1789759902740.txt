What “no Replit tracking” can realistically mean
I can build Kairox with:

No Replit analytics SDK
No Replit runtime dependency
No Replit API calls for normal browsing
No automatic history or profile upload

Local-only profiles, tabs, settings, and downloads

However, no browser can prevent every kind of tracking:

Websites can see requests made to them
Your ISP or network operator can see network activity
Google Play can record installation/update events
A download host can log downloads
If you want to avoid Google Play tracking as much as possible, distribute the signed APK directly instead of through Play Store.

Best free packaging route
Option 1: Android Studio — best for full control
Install Android Studio on your own computer:

Open the native Kairox Android project
Install the Android SDK and build tools
Build a signed release APK
Test it on an emulator and physical phone
Keep your signing key backed up privately
Android Studio is free. This is the most independent option.

Option 2: GitHub Actions — best automated free option
Use a public GitHub repository with an Android build workflow:

GitHub stores the source
GitHub Actions builds the APK
GitHub Releases distributes the APK
The build runs independently of Replit
APK checksums can be published with every release
For private repositories, GitHub’s free build minutes may be limited. Public repositories are generally the most practical free option.

Option 3: F-Droid — best non-Google distribution
F-Droid is appropriate if:

The app is open source
Dependencies meet F-Droid requirements
The build is reproducible
You accept their review process
For direct personal distribution, GitHub Releases is simpler.

Recommended Kairox architecture
For the actual browser:

Kotlin Android host
GeckoView browser engine
Local profile storage
Separate GeckoView session/storage per profile
No Replit runtime
No remote telemetry by default
User-controlled route settings only
No unknown public proxy rotation
No CAPTCHA solving or access-control bypass
No silent cloud sync
For iOS, Android GeckoView cannot simply be reused. iOS would require a separate WebKit-based implementation and App Store review.

Release security checklist
Every production APK should have:

A user-owned signing key
A permanent backup of that key
A unique Android versionCode
SHA-256 checksum
Clean-device installation test
Offline launch test
Network request audit
Manifest permission audit
No Replit URLs or environment variables in the release binary
No Firebase, Expo update service, or analytics unless explicitly enabled
Profile export and restore test
The signing key is critical. If it is lost, future APKs may not update existing installations.
